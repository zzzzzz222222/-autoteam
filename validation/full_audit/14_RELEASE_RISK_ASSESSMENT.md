# AutoTeam v0.6.2 Candidate — 14 发布风险评估

> 审计日期：2026-10-03｜本次**不执行**任何发布操作（commit / push / tag / release 均在授权外）。

---

## 1. 风险分层（按审计要求区分六类）

### 1.1 已确认的代码缺陷（CONFIRMED）
共 **18** 项（完整清单见 15 号报告）。其中影响最大的 4 项 HIGH：
- `AT-AUDIT-001` 核心路径并发上限缺失
- `AT-AUDIT-002` ResultStore 跨 run 累积 + 跨任务状态污染
- `AT-AUDIT-003` Replan 空操作但上报「已重规划」
- `AT-AUDIT-004` headline `supported` 计数口径夸大（90% vs 实际 20%）

### 1.2 高风险但未完全验证
- `AT-AUDIT-025` ExecutionTrace 无锁（理论竞态，当前实践安全）
- 团队构建阶段是否缺超时保护（NEEDS_VALIDATION，见 04 §6）
- 前端 Markdown 消毒 / 路径穿越深层校验（NEEDS_VALIDATION，见 09）

### 1.3 测试覆盖不足
- `AT-AUDIT-020` 前端 0 单元测试
- `AT-AUDIT-024` 真实运行样本不足（仅 1 次真实多 Agent；partial/failure 真实路径无样本）
- `AT-AUDIT-026` 无性能/并发压测
- 上述 HIGH 问题之所以能潜伏，正是因为无对应回归测试（见 10 号报告 §3.2）

### 1.4 设计限制（不应误报为 Bug）
- `AT-AUDIT-013` 单例 Registry 不支持多 worker
- `AT-AUDIT-021` `AUTOTEAM_LLM_MAX_TOKENS` 未设置 → length 自愈惰性
- `AT-AUDIT-022` 语法级校验（非空即过），语义空输出可判成功
- `AT-AUDIT-023` Source 仅存元数据，`access_status` 为空（URL 有效 ≠ 内容核验）

### 1.5 最终交付物质量风险
- **最主要**：`AT-AUDIT-004` 会让读者显著高估结论可信度（这是一个「诚实性」而非「正确性」风险）
- `AT-AUDIT-011` 非数值 Claim 完全未核验（20% 的 Claim 走此分支）
- **事实准确率本身：未测量**（未经人工/权威核验，故不报告该指标）

### 1.6 真实环境验证不足
- 本次**严禁新增真实调用**，因此仅能复用既有 1 次真实多 Agent 样本
- 稳定性、跨任务质量、大规模并发均**未验证**

## 3. 发布状态判定

# ⚠️ CONDITIONALLY_READY

**判定依据**：
- 不存在 CRITICAL / 安全泄漏 / 崩溃级缺陷 → 不属 BLOCKED
- 但存在 **4 项确认的 HIGH 缺陷** 与若干未验证风险 → 不属 AUDIT_COMPLETE_WITH_KNOWN_LIMITATIONS
- 证据足以对关键风险作出判断（代码实证 + 1 次真实样本 + 519 项测试）→ 不属 INSUFFICIENT_EVIDENCE

**含义**：当前候选**可以**发布，但前提是**明确接受**下列风险，或先处理建议项。

## 4. 发布前建议处理（按优先级）

### 必须处理或明确豁免（P0/P1）
| 编号 | 理由 | 建议 |
|---|---|---|
| **AT-AUDIT-004** | 直接影响交付物可信度呈现（90% vs 20%） | **强烈建议修**：拆分 `supported`（支撑层级）与 `citation_verified`（引用核验）两个指标，或重命名前一个字段 |
| **AT-AUDIT-002** | 跨任务数据污染 = 数据隔离失效（安全次生） | **建议修**：`run()` 开始时清理 events 或按 `run_id` 分区 |
| **AT-AUDIT-003** | 状态不诚实（显示了不存在的自愈） | **建议修或改文案**：移除 misleading 事件，或诚实标记 “failure propagated” |
| **AT-AUDIT-001** | 真实环境无并发保护 | **建议修**：给 core 路径默认并发上限 |

### 可作为已知限制保留（需在 Release Notes 披露）
- `AT-AUDIT-005/006/007/008/009/010`
- `AT-AUDIT-013`（多 worker 不支持，必须写在部署说明）
- `AT-AUDIT-021/022/023`
- **必须披露**：`AT-AUDIT-011`（非数值 Claim 未自动核验），否则用户会以为全部 Claim 均被核验

### 不阻塞、后续处理（P2–P4）
- `AT-AUDIT-014~019`（LOW）
- `AT-AUDIT-020/024/026`（测试缺口）

## 5. 若选择「按现状发布」的最低要求

1. **Release Notes 必须披露**：多 worker 不支持、并发上限默认缺失、非数值 Claim 未核验、headline supported 口径含义
2. **文档需说明**：建议配置 `AUTOTEAM_LLM_MAX_TOKENS` 以启用 length 自愈
3. 建议**同版本或补丁**修复 `AT-AUDIT-004`（改动小、风险低、收益最高）
